部署前提：单容器部署 CodeX，前端 AHP Client 通过 AHP 协议（HTTP / WebSocket）与 CodeX 交互，不给用户 SSH 远程连接机会，每用户一容器、非 root 运行、断外网（局域网推理服务）、持久化常驻。在此前提下把 V1 的 SubAgent 隔离方案迁移到「主 Agent 方案」：SKILL.md 加密包按触发解密到 /dev/shm，上下文只留 Token，请求时重水合，两级 TTL 自动卸载，工具拦截 + 回复硬脱敏封死全部明文落盘通道。

§0

摘要与关键数字

四条核心结论，先给结论再展开。

结论一 · 主 Agent 方案的差异缺口已被补齐。V1 靠子代理边界让主 Agent 永远不见明文；主 Agent 方案必须把明文注入 LLM 请求，因此补上「回复明文硬脱敏」：模型流入口对 Message / AgentMessage / Reasoning 脱敏，派生副本（TurnItem、task_complete、rollout）全部只在源头取到干净文本 [K1][K7]。

结论二 · 两级 TTL 满足常驻部署。Skill 空闲 600s 卸载、Thread 空闲 1800s 清空；turn 边界与每次模型请求（重水合入口）双触发 sweep，活跃 token 由命中续费保护——单容器常驻零明文积聚 [K1][K8]。

结论三 · 多轮会话语义完整。明文 Skill、加密 Skill 首次触发、TTL 内反复触发、TTL 过期重新触发、多个加密 Skill 并存、跨会话隔离六类场景全部有确定行为（§6 分 Tab 时序图）[K1][K5][K7]。

结论四 · 部署期 fail-closed。未接真实 AES/Ukey 前保持 sdk = "unavailable"，加密 Skill 触发即告警不注入；全部明文只写 /dev/shm（0700、进程命名空间、容量门控、secure wipe），容器销毁即清零 [K1][K6]。

§1

背景与部署前提

单容器 CodeX + AHP Client/AHP 协议 + 无 SSH 的部署前提；从 V1 子代理隔离演进到主 Agent 方案的威胁模型与设计目标。

1.1 V1 到主 Agent 的演进与威胁模型

参考项目（opencode fm-agent-security 插件）以「executor 子代理」为唯一解密执行域：主 Agent 永远只见 Token 与脱敏摘要，明文全程不进 transcript [K4]。本项目按需求改为主 Agent 方案——加密 Skill 由主 Agent 自身触发执行，因此威胁模型从「主 Agent 不可见」变为「明文短暂可见、但任何持久化副本必须为零」[K1]。

1.2 部署形态（单容器 + AHP）

部署形态：单容器部署 CodeX，前端 AHP Client 通过 AHP 协议（HTTP / WebSocket）与 CodeX 交互（thread/turn 提交与事件流），用户没有 SSH 通道；/dev/shm、skill 包、审计日志全部留在容器内不可见 [K3][K1]。

1.3 设计目标

  • 零明文驻留：rollout、历史、审计、API 流均不落明文，明文只在 /dev/shm 与请求瞬间；
  • 常驻可运维：两级 TTL 活动驱动卸载，进程异常由部署侧 healthcheck/重启兜底；
  • fail-closed：真实 SDK 接入前加密 Skill 只告警不注入；
  • 多轮确定性：明文/加密/反复触发/多 Skill/跨会话行为确定（§6 时序图）。
§2

方案设计

从 V1（SubAgent 隔离）迁移到主 Agent 方案：触发识别、Token 化注入、请求时重水合、两级 TTL、工具拦截、回复硬脱敏六项核心决策，逐项展开实现要点与边界情况。

2.1 六项核心设计决策

① 触发识别与解密

SKILL.md frontmatter 声明 metadata.encrypted 与 metadata.encryption（version/key_id/algorithm/package）；loader 命中后调 load_or_register，TTL 内幂等复用，不重复解密 [K5]。

② Token 化注入

context 只注入哨兵 [SENSITIVE_SKILL_TOKEN:{session_id}:{hex}]；rollout/历史零明文；fork 时过滤含 Token 的消息 [K5]。

③ 请求时重水合

rehydrate_framed 在请求发送前替换 Token：信任层级框架 + 原目录 base anchor + 跨会话门禁；明文仅存在于该请求瞬间 [K1]。

④ 两级 TTL 生命周期

Skill 层空闲卸载单目录；Thread 层空闲清空全部；thread/delete 立即清理；请求级 sweep 防常驻积聚 [K1]。

⑤ 工具拦截 guard

Bash/exec_command 读/搜索 Blocked、执行路径改写；view_image 拦截；其余全部工具参数含已知明文 Blocked [K7]。

⑥ 回复明文硬脱敏

模型流入口先脱敏，Message/AgentMessage/Reasoning 全覆盖；TurnItem、task_complete、rollout 同一源头干净 [K7]。

2.2 决策展开

① 触发识别与解密

  • 识别：loader 解析 frontmatter metadata.encrypted: true；SkillMetadata.encrypted / encryption 字段承载（app-server v2 同步为可选字段）[K5]。
  • 解密入口：build_skill_injections 加密分支 → load_encrypted_skill → EncryptedSkillRuntime::load_or_register(session, skill, <name>.zip.enc) [K5]。
  • 幂等：注册表命中且未过期 → 直接复用 Token，SDK 解密零调用；内容级去重（相同明文共享一个 hex Token）[K1]。
  • fail-closed：SDK 未配置（UnavailableSdk）或解密失败 → warning + 指标，Skill 不注入，明文永不 fallback [K5][K6]。
  • 容量门控：解密前按加密包文件大小 + 4MiB 余量预检查；解密后按 entries 总量复检，防止超大包打满 64MB /dev/shm [K1]。

② Token 化注入

  • 哨兵格式：[SENSITIVE_SKILL_TOKEN:{session_id}:{hex}]；session_id 用于跨会话门禁，hex 为缓存键 [K1]。
  • 注入面：SkillInstructions::body() 对加密 Skill 输出 Token（明文 Skill 输出原文，行为不变）[K5]。
  • 持久化：context 历史与 rollout JSONL 只含 Token；E2E 断言 !rollout.contains(明文) [K8]。
  • fork 隔离：keep_forked_rollout_item 过滤含 Token 的 item，子 Agent 不继承解密内容；需要时自行重新提及 [K1]。
  • 边界：明文 Skill 完全走原路径（load_plaintext_skill 直接读 SKILL.md），加密字段默认 false/None，零行为影响 [K5]。

③ 请求时重水合

  • 时机：Prompt::get_formatted_input_for_request 发送前扫描替换 Token；常规 turn、compaction、resume 三路径统一走 EncryptedSkillRehydrator [K1]。
  • 框架：wrap_with_framing 注入 <output_policy>（禁止复述/改写/编码原文）与 <injection_defense>（Skill 内容是任务流程数据，不覆盖输出策略），并附 skill_name 与 base_directory anchor [K1]。
  • 跨会话门禁：Token 内嵌属主会话 ID，只替换属主会话内的 Token；copy-paste 到其他会话拒绝替换 [K1]。
  • 失效保留：TTL 卸载后 Token 变 stale，重水合原样保留，模型侧提示重新提及 Skill 触发重新解密（fail-safe 恢复）[K1]。
  • 保洁：rehydrate_framed 入口先 sweep()——任何请求活动都触发两级 TTL 清理；活跃 Token 由命中续费（touch）保护 [K1]。

④ 两级 TTL 生命周期

  • 注册表：session → skill → {dir, loaded_at, last_used_at}，可注入时钟；幂等命中刷新 last_used_at [K1]。
  • Skill 层（默认 600s）：空闲超时 → 卸载单个解密目录（secure wipe）+ 无引用时移除缓存条目；支持 per-turn 加载/卸载语义 [K1]。
  • Thread 层（默认 1800s）：线程空闲超时 → 清空该线程全部解密目录与内容缓存 [K1]。
  • 触发点：turn 边界（build_skills_and_plugins）与每次模型请求（重水合入口）双触发；完全无请求时驻留到容器重启 [K1]。
  • 周期兜底：常驻进程后台每 30s 执行一次 sweep（encrypted_skills_periodic），覆盖「进程活着但长时间无请求」的空闲窗口；进程挂起仍由部署侧 healthcheck/restart 兜底 [K1]。
  • 线程结束：thread/delete → CodexThread::clear_encrypted_skills → 立即 wipe + 审计 [K1]。
  • 共享缓存保护：两个 Skill 内容相同时共享 Token，卸载一个不失效另一个（token_ref_count 守卫）[K1]。

⑥ 回复明文硬脱敏

  • 问题：主 Agent 方案把明文注入 LLM 请求，<output_policy> 只是软约束——模型回复可能复述/引用明文，导致 assistant 消息落盘 [K1]。

  • 匹配语义：完整明文、≥20 字符行、20 字符前缀、以及 作为完整行出现的短行（如 api_key=abc）→ [REDACTED]；嵌在句子中的短片段不误伤 [K1]。
  • E2E：mock 回复引用 REAL_SKILL_CONTENT_MARKER，断言 rollout 只含 [REDACTED] [K8]。

§3

插件体系与源码修改

Codex 的扩展能力边界，以及本需求为何必须修改核心源码、改了哪些文件。

3.1 Codex 插件体系

Codex 插件体系分三层：

  • Extensions（codex-extension-api）：ExtensionRegistry + contributors（config / turn_input / context / turn_item / thread_lifecycle），承载 web-search、skills 展示、image-generation、connectors 等外围能力；可注册工具、上下文片段与生命周期事件，但不能改写核心请求形成与历史持久化；
  • Hooks（hooks.toml）：pre_tool_use / post_tool_use / session 事件，进程外、按工具名/字符串匹配，可拦截与改写工具入参，但拿不到解密运行时状态（注册表、路径映射、明文缓存、TTL）；
  • core-plugins：skills/plugins 的分发与列举，不参与单次请求的解密/注入。

3.2 为什么插件无法实现需求

需求无法通过插件实现，原因如下：

  • 注入与重水合发生在 build_skill_injections 与 Prompt::get_formatted_input_for_request（core 内部关键路径），扩展 contributor 无法在“模型请求形成”边界做 Token→明文替换；
  • 工具拦截需要按“脚本文件目标 + 执行白名单”分级并做路径改写，依赖会话注册表；hooks 无此状态且只能字符串匹配；
  • 明文驻留面覆盖 ResponseItem / TurnItem / task_complete / compaction / rollout 多处持久化副本，分布在 session 与流处理内部，插件无法在每个落盘点做结构保证；
  • 需要新增协议/元数据字段（SkillMetadata.encrypted/encryption、app-server v2）与配置（[encrypted_skills]），扩展 API 没有这些类型。

3.3 为什么修改源码

需求本质是在“模型请求形成”与“历史持久化”两个核心边界做结构保证，这些边界不是扩展点；因此采用独立 crate + 有限薄接线，把侵入控制在最小（核心仅接线点，加解密逻辑全部在 codex-encrypted-skills 内）。

一个独立 crate + 三条薄接线：加载注入、请求重水合、工具分发前置拦截；明文只存在于 /dev/shm 与请求瞬间。

关键流程

从「模型提及 Skill」到「明文消失」的完整生命周期：主流程、两级 TTL 状态、特殊路径与审计事件。

5.1 主流程（触发 → 解密 → 注入 → 执行 → 卸载）

① 触发模型提及 Skill，loader 命中 frontmatter encrypted 标记
② 解密容量门控 → SDK 解密 → 写 /dev/shm（0700）→ 缓存明文
③ 注入context 写入哨兵 Token，rollout 零明文
④ 重水合请求发送前 sweep + Token→明文框架（仅请求瞬间）
⑤ 执行工具调用过 guard：路径改写/拦截/导出明文拦截
⑥ 脱敏回复流入口脱敏，TurnItem/rollout 同源干净
⑦ 卸载Skill 空闲 600s 卸载；Thread 空闲 1800s 清空
⑧ 清理thread/delete 立即 secure wipe + 审计事件

步骤输入 → 输出失败/边界路径

⑥ 脱敏模型回复 → [REDACTED] 文本短片段嵌入句子 → 保留（纵深边界）

5.3 两级 TTL 状态机

Skill 状态：loaded/fresh（TTL 内，幂等命中）→ 空闲超时 → stale（Token 保留、明文已卸载）→ 重新提及 → reloaded（重新解密）。

Thread 状态：active（turn/请求活动续费）→ 空闲超时 → cleared（全部目录/缓存清除）→ 下次提及重建。

触发时机：turn 边界（build_skills_and_plugins）与每次模型请求（rehydrate_framed 入口）双触发；完全无请求时驻留到容器重启，/dev/shm 随容器销毁自动清空 [K1]。

5.4 特殊路径

  • compaction（上下文压缩）：压缩请求同样重水合 Token；摘要从已脱敏的历史提取，RolloutItem::Compacted 无明文（结构保证，优于 V1 的 prompt 软约束）[K1]。
  • resume / stale token：会话恢复后 Token 仍指向已卸载内容 → 原样保留，模型重新提及触发重新解密（fail-safe）[K1][K8]。
  • fork 隔离：keep_forked_rollout_item 丢弃含 Token 的 item；子代理重新提及自行解密 [K1]。
  • 进程重启：per-process 命名空间 + pid 存活清理；pid 复用极端场景由容量门控与审计轮转兜底 [K1]。

5.5 审计事件

事件触发关键字段

tokenizationToken 生成session_id、skill_name

钻取：幂等与去重

同一会话内相同明文只存一份 Token（cache 去重）；两个 Skill 内容相同时共享缓存，但各自注册表条目独立，卸载一个不失效另一个（token_ref_count 保护）。[K1]

钻取：跨会话门禁

Token 内嵌属主会话 ID；重水合只替换属主会话内的 Token，跨会话 copy-paste 拒绝替换，防止一个会话读到另一个会话的明文。[K1]

5.6 进程异常与明文驻留（TTL 失效边界）

TTL 是进程内活动驱动的惰性清理：sweep 在 turn 边界、每次模型请求（重水合入口）以及常驻进程的后台周期任务（30s）三处触发。进程异常时仍存在明确边界：

  • 进程挂起（hang）：事件循环不再推进，进程内 sweep（含周期任务）都不执行——解密内容会超过 TTL 驻留在 /dev/shm，直到进程恢复、被杀重启或容器销毁；
  • 进程被杀 / 崩溃（kill/crash）：内存中的注册表与缓存随之消失，但 /dev/shm 下 p<pid> 目录仍残留；下次任何 CodeX 进程启动时 init_mem_root_once 按 pid 存活状态清理删除；容器销毁则 /dev/shm 整体清空；
  • 结论：TTL 覆盖「进程活着且活动或空闲」；进程挂起仍需部署侧 watchdog。
已实现：后台周期 sweep（30s，encrypted_skills_periodic）解决「空闲但无请求」的驻留；部署缓解：healthcheck + 自动重启覆盖挂起（挂起超时杀进程重启，触发启动清理）；单容器无 SSH 下用户无法读取 /dev/shm；启动 pid 清理覆盖崩溃残留。

5.7 Skill 从上下文卸载的策略（原版 / 明文 / 加密）

三种形态的 Skill 在「上下文驻留」与「存储卸载」上的语义完全不同，多轮会话行为据此确定：

形态上下文（context）存储（/dev/shm、缓存）多轮行为
原版（未启用加密的 Codex 普通 Skill） SKILL.md 原文注入后长期保留，直到上下文压缩/截断；无 Token、无 TTL 不涉及解密存储 每次提及重复注入原文；旧副本随压缩移除，无显式卸载语义
明文 Skill（加密功能启用但未标记 encrypted） 同原版：load_plaintext_skill 直接注入原文，长期保留至压缩 不写 /dev/shm、不进 TTL 注册表 与启用加密功能前完全一致，零行为影响
加密 Skill 只注入哨兵 Token，Token 本身不因 TTL 从上下文移除；明文只在重水合请求瞬间出现 明文按两级 TTL 卸载：Skill 600s 卸载单目录，Thread 1800s 清空全部；secure wipe TTL 内反复提及复用同一 Token；过期后 Token 变 stale（不再重水合），重新提及触发重新解密并生成新 Token
关键区分：加密 Skill 的「卸载」发生在存储层（/dev/shm 与内容缓存），上下文层的 Token 长期保留；TTL 过期只让 Token 失去重水合能力（stale），不删除历史消息。重新提及后新 Token 注入，旧 Token 保留但不再替换。

§8

部署与安全

部署前提逐项落地的结论、推荐配置与验证清单；残余风险明示。

8.1 单容器部署拓扑（当前方案）

层形态安全边界
CodeX 执行容器（单容器）每用户一容器；非 root 运行；持久化常驻不开 SSH；对外只暴露 HTTP / WebSocket（app-server 网关）
AHP Client（前端）用户唯一交互入口，经 AHP 协议（HTTP/WebSocket）访问 CodeX（thread/turn 提交与事件流）用户无 shell 通道；/dev/shm、skill 包、审计日志对用户不可见
推理服务局域网内（host 或同网段）模型 API 由 CodeX 进程发起，不经沙箱 shell；白名单可达
Workspace挂载进容器的工作目录加密 skill 包位于容器私有路径（codex_home/skills），不混入 workspace

8.2 推荐配置

# config.toml（单容器 CodeX）
[encrypted_skills]
sdk = "unavailable"              # 真实 SDK 接入前 fail-closed
skill_idle_ttl_secs = 600        # Skill 层空闲 TTL
thread_idle_ttl_secs = 1800      # Thread 层空闲 TTL
audit_path = "/data/codex/audit/encrypted-skills-audit.log"  # 持久卷，非 root 可写

[sandbox_workspace_write]
writable_roots = ["./", "/dev/shm/fm-agent-security"]
network_access = false           # shell 断网；推理服务由 host 进程调用

8.3 部署验证清单

  1. 单容器边界：确认容器未开 SSH、无 shell 转发；HTTP/WS 为唯一入口；/dev/shm 与 skill 包对用户不可见
  2. 进程健康：容器 healthcheck + 自动重启；挂起超时杀进程重启，触发启动清理（TTL 失效边界兜底）
  3. bwrap 可用性：容器内实测 bwrap --ro-bind / / /bin/true；不可用则 guard-only + 容器网络收紧 [K1]
  4. /dev/shm：建议 ≥256MB，容量门控余量可调（set_min_free_bytes）
  5. skill 包位置：只放容器私有路径（codex_home/skills），不混入 workspace
  6. 审计持久化：audit_path 指向非 root 可写持久卷，验证 10MB 轮转与重启保留
  7. 网络策略：容器 --network none 或出口白名单；局域网推理服务经白名单可达
  8. TTL 保洁：turn 边界 + 每次请求双触发；无请求时驻留至容器重启（/dev/shm 自动清空）
  9. 容器 ACL：/dev/shm 非隔离边界，同 uid 进程可读 → 必须容器级 ACL + 网络收口
  10. 真实加密：Ukey/AES 接入前保持 unavailable；接入后 sdk 切换并回归全矩阵

8.4 残余风险

风险缓解状态
write_stdin 无 pre-tool payload，无法拦截既有 shell 会话输入路径随机化 + 输出脱敏；模型无法获知 fm_skill_security_<hex> 地址已记录
MCP/扩展工具路径探测（如 list /dev/shm）参数引用 mem root/解密目录即 Blocked（storage_probe）；受限部署仍建议不启用带文件访问能力的 MCP server已修复
文本工具输出明文（多步流程合法使用）模型上下文可见（临时）；rollout/API 流落盘前 [REDACTED]；脚本源码不可见；apply_patch 与非 shell 工具参数 Blocked已收口
短片段变形（<20 字符裸嵌入句子）引号包裹片段（≥12 字符）已脱敏；裸嵌入句子的变形属纵深防御边界部分缓解
真实 AES/Ukey 未接入当前为 deflate 模拟加密；部署期 fail-closed待 Ukey
bwrap 容器内可用性未实测部署清单第 2 项验证；不可用则 guard + 网络策略待部署实测
进程挂起时 TTL 不触发（明文驻留超时）后台周期 sweep（30s）已实现；healthcheck + 自动重启 + 容器销毁兜底已实现 + 部署兜底
