输入侧注入检测：
分层安检，不押单点

Prompt injection / jailbreak 进入 Agent 之前的识别、归一化与过滤

Agent 的用户输入侧威胁分两类：直接注入（越狱、角色扮演、系统提示与 Skill 提取）与间接注入（载荷藏于网页/邮件/工具返回）。全部检测拦截方案可归入六类 I/O 形态——encoder 分类器、托管 verdict API、生成式判定、政策推理、token 级流式、轨迹审计，再叠加归一化/spotlighting/canary 三类非模型技术与架构兜底。工程共识是一条级联安检管线：规则归一化（<1ms）→ 小分类器（20–100ms）→ LLM judge（秒级），95% 以上流量在前两层终结。中文场景自托管首选 Qwen3Guard（119 万条训练数据、中文占 26.6%）；而检测层的天花板已被实测击穿——12 种防御被自适应攻击 >90% 绕过，高危操作必须靠架构兜底。

§0 · 摘要与结论速览

问题定义、六形态方案地图、三条核心结论

任何单一检测器都不可作为唯一防线——分层检测不是选型偏好，是威胁模型本身决定的必然架构。

问题定义。 Agent 面临的输入侧威胁分两类：直接注入——用户直接在对话中发起越狱、角色扮演绕过、系统提示与 Skill/工具配置提取；间接注入——攻击载荷藏匿于网页、邮件、文档、工具返回值等外部内容，经检索与工具调用进入上下文后劫持行为。本报告聚焦前者，仅在边界处讨论间接注入。这已是 2026 年 Agent 平台的基础设施级问题：OWASP LLM Top 10 将 Prompt Injection 列为 LLM01 头号风险；实测显示 80% 以上部署应用的系统提示可被简单套取，而 Agent 的系统提示往往包含工具 schema、业务流程与内部知识，泄露即等于交出攻击蓝图。Agent 拥有工具执行能力，一次成功的注入不只是"说错话"，而是真实的外部动作——检测拦截从"体验问题"升级为"安全问题"。

方案地图：六类 I/O 形态。 现有检测拦截方案可归纳为六类：① encoder 分类器（Prompt Guard 2、DeBERTa 系，毫秒级、标签输出）；② 托管 verdict API（Lakera Guard、Azure Prompt Shields、AWS Bedrock Guardrails，一次调用返回判定）；③ 生成式判定（Qwen3Guard、Llama Guard，输出安全等级与类别）；④ 政策推理（gpt-oss-safeguard，带自定义政策链式推理，慢但可解释）；⑤ 流式 token 级（生成过程中实时拦截）；⑥ 轨迹审计（AgentDoG 等对 Agent 行为序列做事后/事中诊断）。叠加三类非模型技术——输入归一化、spotlighting 分隔标记、canary 金丝雀令牌，以及架构兜底——最小权限、信息流控制、人机确认。本报告全部章节即这张地图的逐格展开（§10 六形态总表）。

三条核心结论

  • 分层管线是唯一正解。 单点检测器在自适应攻击下普遍失效（>90% 绕过），可行架构是：快路径分类器毫秒级放行绝大多数流量 → 深检模型/政策推理处理可疑样本 → 会话级风险分累计多轮信号 → 轨迹审计兜底事后追责 → 最小权限与信息流控制限制爆炸半径。归一化层被严重低估：不做它，emoji/Unicode 混淆可 100% 绕过下游所有检测器。
  • 中文场景自托管首选 Qwen3Guard。 多语言、三档分级、中文训练数据充足（119 万条训练数据中文占 26.6%，公开护栏中最高）；中文注入检测数据集基本空白，英文检测器对中文接近失明，托管侧只有 Azure（官方中文训练）与 Lakera（宣称多语言）可选。慢路径配 gpt-oss-safeguard 做可解释的政策推理复核。
  • 检测不保证完备，必须架构兜底。 OpenAI/Anthropic/DeepMind 联合研究显示 12 种检测类防御被自适应攻击 >90% 绕过；防系统提示/Skill 泄露的真正兜底是"系统提示零机密 + 输出侧相似度比对 + 工具最小权限"——假设提示词终将泄露来设计系统。

§1 · 威胁模型

输入侧要拦的不是一类攻击，而是十几个攻击族

OWASP Top 10 for LLM Applications（2025）将 Prompt Injection 列为第一大风险 LLM01，并明确指出"RAG 和微调都不能完全缓解"。

理解所有手法的统一钥匙是 Wei et al.（NeurIPS 2023）提出的两条根本失效机制：其一，目标竞争——预训练/指令遵循目标与安全目标冲突时安全目标常落败，角色扮演、prefix injection、拒绝抑制都利用此机制；其二，泛化错配——模型能力泛化远广于安全训练覆盖的分布，Base64、低资源语言、密码对话、ASCII art 都利用此机制。分类不是目的，识别机制才能反推检测手段。

DAN

角色扮演与虚构包装

让模型扮演"无规则的另一个 AI"；组合攻击中最高频成分（出现 331 次）。

HackAPrompt 类挑战数据上 DAN 类总成功率 31.8%。DeepInception 用多层嵌套虚构场景稀释对齐信号，诱导内容可绕过 LlamaGuard 与 OpenAI 检测 API。prefix injection（强制以 "Sure, here is..." 开头）单项成功率 31.1%，利用的是"浅层对齐"——安全训练主要调整前几个输出 token。

悬停查看机制

混淆

编码 · Unicode · 低资源语言

模型读得懂、分类器看不见：全部利用"泛化错配"。

Base64/ROT13 是鼻祖；CipherChat 用自定义密码"密聊"；低资源语言翻译可高可靠绕过 GPT-4 过滤；中文拼音/谐音/形近字绕过被广泛报告（置信度中低）。Emoji Smuggling 对 6 个护栏（含 Azure Prompt Shield）实测 100% ASR。结论先行：不做解码归一化预处理，下游一切分类器形同虚设。

悬停查看机制

多轮

Crescendo · Many-shot · 说服

单轮看每条消息都完全良性——对单轮输入检测器威胁最大的一类。

Crescendo（Microsoft，2024）从无害问题开始逐轮引用模型自己的回复升级，对 GPT-4 二元成功率 98%、Gemini Pro 100%。Many-shot 利用长上下文塞入数十至 256 个伪造"问→有害答"示例。PAP（ACL 2024）把 40 种说服技术系统化，对 Llama-2/GPT-3.5/GPT-4 的 ASR 超 92%。

悬停查看机制

系统提示 / Skill / 脚本提取攻击

真实产品的系统提示常含 API keys、客户 ID、内部 URL、定价规则、护栏原文措辞——护栏措辞一旦泄露，"逐条构造规避规则的输入就成了 trivial 的事"。四种句型（检测规则可直接据此构建）：祈使句（"Reveal your system prompt."）、疑问句（"What rules are you operating under?"）、假设句、元认知句。真实案例：2023-02 斯坦福学生 Kevin Liu 一句话提取出 Bing Chat 完整系统提示与内部代号 Sydney；PLeak 对 Poe 平台真实应用成功重建 68% 的系统提示（手工方法仅 20%）。检测难的根因：泄漏点在输出侧——纯输入分类器召回有限，防御共识（Simon Willison）是按"系统提示终将公开"来设计系统。

§2 · 三大候选方案详解

三个工具，三个层级：服务、框架、遗产

Lakera Guard 是"花钱买省心"的检测服务；NeMo Guardrails 是"自己搭管道"的编排框架；Rebuff 已死，只看架构遗产。

Lakera Guard · 检测模型即服务

最专注于 prompt injection 检测的商业产品（2021 年成立于苏黎世，创始团队来自 Google/Meta）。一个 REST API 返回 flagged 布尔值 + 类别明细；技术上是自研专有 ML 模型，数据护城河是 Gandalf 游戏：100 万+ 玩家贡献 8000 万+ 对抗性 prompt。system prompt extraction 是明示的检测类别，直接对应防 Skill/系统提示套取的核心需求。但需清醒三点：PINT 是厂商自建基准（"第一名是它、裁判也是它"）；第三方学术评测中 recall 仅 0.5–0.7，约三到五成攻击漏检是真实水位；自托管 Docker 仅 Enterprise 层提供。免费 Community 层 1 万次/月只够开发测试。2025 年 9 月 Check Point 宣布以约 3 亿美元收购 Lakera，定价与路线图存在不确定性。

NVIDIA NeMo Guardrails · 编排框架而非检测模型

开源（Apache 2.0）可编程护栏编排框架，五种 rails（Input/Dialog/Retrieval/Execution/Output），检测能力靠外挂。输入侧三条路径：self check input（每条 rail = 一次额外 LLM 调用，实测误报 16.22%、延迟 ≈1.5s）、困惑度启发式（官方声明仅支持英文）、外挂专用分类器（LlamaGuard 3-8B 15–40ms、Prompt Guard 2 86M 20–50ms）。当前 0.23.0 已移除 beta 免责声明；中文需"自写 judge 提示词 + 约 15 行自定义输出解析器"组合。部署三形态：Python 库 / sidecar server / K8s 微服务。

Rebuff 不能用于生产：已归档无安全补丁、FPR 0.68、29 秒延迟、绑定付费 OpenAI+Pinecone，任何一条都足以否决。但它的四层架构思想——快规则先筛 → 慢判别复核 → 向量库做"攻击记忆" → canary 检测泄露并把样本回流自硬化——值得在自研管线中完整复刻。

§3 · 方案全景对比

PINT 榜第一名是它，裁判也是它

Lakera 自建基准上自家产品领先第二名约 6 个百分点——读榜之前，先读利益冲突。

PINT（Prompt INjection Test）是 Lakera 自建开源基准：4,314 条输入，含注入/越狱/硬负例三类，指标为 balanced accuracy。完整数据集不公开（公开版仅 4 条示例），官方理由是 Goodhart 定律——"当度量成为目标，它就不再是好的度量"。两点必须清醒：其一，厂商自建基准存在天然利益冲突，读者应按第三方独立复现交叉验证；其二，口径冲突需并列——CourtGuard 论文引用旧版数据称 Lakera 得分仅 92.55%，新版 95.22% 属基准/模型迭代的时间性差异，本报告以现版为准并保留旧值。

可自托管开源分类器：两条关键规律

其一，低 FPR 下小模型集体失效：PromptShield 基准显示所有 DeBERTa 级小模型在 TPR@0.1%FPR 上只有 0–12%，而 8B 级检测器可达 71.45%——实用的低误报阈值恰恰是 encoder 小模型的死区。其二，微调自家数据便宜且有效：Knostic 合并 17 个公开数据集微调 DeBERTaV3 后 accuracy 约 99%、FPR 从 0.017 降到 0.002；RAPIDS 论文报告 LoRA r=8 只训 2.3M 参数、单张 L40S 一小时内、每轮成本 $1–2，垂直域 recall 从 0.53 提到 0.985。

静态基准 vs 自适应攻击，两个口径必须同时呈现。 Meta 口径 Prompt Guard 2 86M 在 AgentDojo 拦截率 81.2%（3% 效用损失）；独立 SoK 研究则显示自适应多轮攻击下各 guardrail 的 ASR 仍 >90%。静态榜回答"谁过滤脚本级攻击最干净"，自适应口径回答"坚定的攻击者能不能过去"——两个问题的答案都真实。

选型小结。 纯英文低延迟选 Prompt Guard 2；有中文流量选 Qwen3Guard 或 Azure Prompt Shields（云侧唯一官方中文训练）；间接注入场景优先支持文档检测的 Azure/AWS；无论选谁，用自家 benign 流量做 LoRA 微调降误报，成本仅 $1–2/轮。

§4 · 不依赖检测模型的防御技术

归一化是前提，规则是闸门，spotlighting 是主力变换

这些技术单独任何一项都拦不住坚定的攻击者，但其中几项便宜到没有理由不做。

预处理归一化是被严重低估的一层。 emoji/Unicode 混淆对包括 Azure Prompt Shield 在内的 6 个护栏实测 100% 绕过——攻击者只要先过一道编码或 Unicode 变换，后面所有"高分检测器"的评测数字全部作废。任何检测管线在调用任何检测器之前必须先做：Unicode NFKC 规范化、去零宽字符与 Bidi 控制符、编码识别与解码、长度与结构异常检查。这层成本不足 1ms，纯字符串处理，它不拦截任何攻击本身，但缺了它，其他层等于裸奔。

Spotlighting 是纯推理时性价比最高的变换。 Microsoft Research 的思路：在拼接前对不可信文本做变换，让"这是数据不是指令"的信号持续可见。datamarking 和 encoding 在 GPT-3.5/GPT-4 上将间接注入 ASR 从 >50% 降到 <2%，零额外模型调用；但 LLMail-Inject 挑战赛的 370,724 个自适应攻击提交证明坚定的攻击者仍能部分突破。金丝雀 token 默认实现检测率为 0，加显式处理指令后才部分有效，定位是事后告警。CaMeL（Google DeepMind + ETH）是少数能在推理时部署且提供近确定性保证的方案：AgentDojo 上成功攻击数从 233 降为 0，代价是任务解决率 84%→77%。

§5 · 基准与评估方法

"测分高 ≠ 防御好"：评估的四个坑

中文注入检测数据集基本空白；静态数据集测不出"知道防御存在后会迭代绕过"的攻击者。

FPR 要换算成生产成本。 漏报 = 安全事故，误报 = 正常用户被拦、直接流失，两者成本非对称：FPR 1.1% 约等于"百条良性误伤一条"，用户基本无感；FPR 13.2% 则不可用。实务上以 QPS × FPR × 单次误伤成本 对比 攻击流量 × FNR × 单次入侵损失 选 ROC 工作点，而非盲目最大化 balanced accuracy。自适应攻击者问题：微软 LLMail-Inject 是目前最大的自适应评估——839 名参与者提交去重后 208,095 条唯一攻击，端到端成功率仅 0.8%/0.3%，部分防御平均要数百次尝试才首次被破；"首次成功所需尝试数"比静态 ASR 更能反映真实鲁棒性。

中文评估现状：基本空白。 现实做法三条腿：(a) PINT 的 1,298 条非英文子集明确含中文；(b) Meta CyberSecEval 3 多语言注入集（英文越狱集机翻 15 种语言，promptfoo 已内置插件）；(c) 自建中文种子集 + 机翻扩增，作为私有 held-out。注意现有中文资源评的是模型抗越狱，不是输入分类器。

§6 · 工程落地：级联架构

三个数量级的延迟分层，决定级联是唯一可行形态

规则 <1ms、小分类器 20–100ms、judge 秒级——让 95%+ 流量终结在前两层，judge 层按 1–5% 升级率计费。

学术与生产实现高度一致。GuardChain 三级管道：正则（<0.2ms）→ CPU 分类器（3–50ms，$0.17–2.77/百万请求）→ GPU 模型（24.3ms，$6.80/百万请求），实测仅 ~2% 分布内流量升级到 GPU 级。Spheron 生产栈：Prompt Guard 2 86M 快闸 → 可疑升级 LlamaGuard 3 8B（INT4 后 p50 ~20ms、VRAM 4GB），总输入轨 p50 20ms / p99 50ms，压 p99 <80ms 靠三板斧：小模型快筛、INT4 量化、5ms 窗口异步攒批。LlamaFirewall 分层：PromptGuard（<20ms，每请求必过）→ AlignmentCheck（仅高风险会话开启）→ CodeShield。

部署形态上"网关强制入口"是主线：SDK 不能作为唯一防线——它把安全性建立在开发者合规性上。正确姿势是内部 LLM 流量全部强制走反向代理（Bifrost 5000 RPS 压测每请求仅增 11µs），对外功能再叠加边缘层。流式（SSE）是输入层的核心约束：pre-call 输入检测与主 LLM 调用并行下发，检测先于首 token 完成则流式零延迟；而 post-call 输出检测必须攒齐全部分片再判，流式体验退化为非流式。fail-open vs fail-closed 必须显式决策：网关心智默认 fail-closed。

拦截动作与会话级风险分

动作谱系：block（网关直接 400/安全拒答）、sanitize/rewrite、flag/log-only——新策略先 logging_only 观察再转阻断是标准上线流程；HITL——按工具粒度配置审批。两个关键工程细节：双阈值灰区（低于低阈值放行、高于高阈值阻断、中间走二次分类器或人工）；级联必须分层归因，记录是哪一层拦的。单轮分类器对 Crescendo 类多轮攻击系统性失效，工程应对是每会话维护分类器置信度的 EMA：单轮 0.4 不拦，连续三轮 0.4 即构成真实升级；会话状态放网关层，键为 (session_id, caller_token) 双维度，防止攻击者顺序攻击各 Agent 而每个 Agent 无共享记忆。

GPU 成本与容量结论。 Prompt Guard 2 86M：FP16 ~550MB / INT8 ~280MB 显存，GPU 上 0.8–2ms/请求、500–1200 req/s，单卡 g5.xlarge 约 $4.03/百万请求；LlamaGuard 3 8B INT4 约 4GB 显存。一张 T4/A10G 同时承载 86M（<1GB）+ INT4 8B（~4GB），支撑数百 req/s 的两级检测；CPU-only 降级路径吞吐降 1–2 个数量级，只适合作旁路。

§7 · 前沿趋势（2025–2026）

未来一到两年，胜者是分层组合

纯"大模型自防御"和纯"静态分类器"单点押注均已过时。

流式 token 级检测已从概念变为可部署组件：Qwen3Guard-Stream 逐 token 输出安全标签、触发即中断；FreoStream 用未来感知推理把 Qwen3Guard-Stream-8B 的平均 ASR 从 17.88% 降到 7.90%。系统提示泄露是被低估的专门战场：2026 年 6 月对 6 大商业平台 1200 个应用的实测显示，超过 80% 的部署在真实对抗查询下会泄露系统提示，常连带泄露第三方 API key，机理被归结为 attention drift。

单靠静态检测器对自适应攻击必然失守，纯检测路线已被判死刑——检测层的正确定位是"抬高攻击成本、过滤脚本级攻击"，不是兜底。

— The Attacker Moves Second（OpenAI / Anthropic / DeepMind 联合），2025-10

背景对 12 种已发表检测/训练类防御（PromptGuard、PIGuard、Model Armor、StruQ、Circuit Breakers 等）做自适应攻击，全部以 >90% 成功率绕过。 唯一例外CaMeL 这类架构隔离部分幸存。

落到输入侧选型，两句话：其一，检测器要买"快 + 多语 + 流式"这一档（Qwen3Guard-Stream / PromptGuard 2 / YuFeng-XGuard-0.6B），流式头已从加分项变为标配；其二，采购与架构设计时预留与架构层的接口——CaMeL 式能力控制、FIDES 式信息流标签、AlignmentCheck 式轨迹审计。2026 年新论文进一步坐实：轨迹级护栏已从概念走向 SOTA（AgentDoG 1.5，0.8B 起步、可在线 Pre-Reply，§9），政策推理护栏补齐了"慢路径可解释深检"一格（gpt-oss-safeguard，§8）。

§8 · gpt-oss-safeguard 与 ShieldGemma

政策推理护栏：政策 + 内容进，判定 + 理由出

gpt-oss-safeguard 是"慢路径政策推理审计器"，不是在线闸；ShieldGemma 词表无注入类、仅英语——本场景直接排除。

gpt-oss-safeguard（OpenAI，2025-10-29，research preview）是开放权重"安全推理模型"：120b（117B 总参/5.1B 激活）与 20b（21B/3.6B）两档，Apache 2.0。它与传统分类器的根本区别在于原理——不在标注数据上学固定决策边界，而是推理时直接读取开发者自写的书面安全政策（bring your own policy），用思维链解释政策并给出判定：输入 = 政策文本 + 待判定内容，输出 = 判定结论 + 完整推理过程。方法源自 OpenAI 内部 Safety Reasoner（已在 Sora 2、GPT-5、ChatGPT Agent 生产栈使用）。I/O 契约走 harmony 格式：developer/system 放政策（官方建议 400–600 token 最优），user 放待判定内容（用户消息/模型回复/完整对话均可）；输出由政策中的 output instructions 显式定义（二值 0/1 或 JSON），推理链走隐藏 analysis 通道，reasoning effort 三档可调。上下文 131,072 token——128K 级，装得下完整会话；20b 经 MXFP4 后 16GB 显存消费级 GPU 即可运行。

成绩与局限必须并排读。 官方内部多政策准确率（所有政策全对才算对）：120b 46.3%、20b 43.6%，超 gpt-5-thinking 的 43.2%；第三方 ToxicChat 独立榜（2026-03）20b F1 79.9% 居开源护栏榜首（Qwen3Guard-8B 73%、LlamaGuard3-8B 51%）；ML-Bench 多语言 F1 0.85 远超同类，第三方中文 F1≈80。但三条局限同样官方自认：其一，秒级延迟——全生成式 CoT 推理，比 BERT 级分类器慢 1–2 个数量级，"难以对全量流量逐条推理"；其二，官方自认注入/越狱基准弱于 gpt-oss 基座（20b 低 1–5 分）——对注入检测场景这是值得警惕的信号；其三，CoT 可能含幻觉，不应展示给终端用户。定位即慢路径：对快路径预筛出的可疑流量用自定义注入政策做深检与可解释审计——这正是 OpenAI 官方推荐的"小分类器预筛 + Safety Reasoner 深检"双层架构。

ShieldGemma：三条理由排除。 Google 基于 Gemma 2 的 SFT 内容安全分类器（2B/9B/27B，固定 4 类内容危害）：① 词表里没有 prompt injection / jailbreak 这一类，越狱提示往往不含仇恨色情语义会被判 No；② 仅英语训练，RabakBench 明示 supports only English，多语言实测垫底；③ ToxicChat 独立榜大档反而更差（27B 仅 48%）。另注意 ShieldGemma 2 是 4B 纯图像分类器，文本线实质停在 Gemma 2 代；Gemma ToU 非 OSI 开源（禁用用途政策 + 向下游传递义务），企业用需法务审查。

组合启示。 快路径用 Prompt Guard 2 / Qwen3Guard 毫秒级预筛，慢路径用 gpt-oss-safeguard-20b 以自定义注入政策做可解释深检——政策即代码，政策的版本管理与回归测试成为新工作。

§9 · AgentDoG 与 2026 最新进展

轨迹级诊断护栏：从概念走向 SOTA

AgentDoG 1.0/1.5 均为 arXiv 正式论文（2026-01 / 2026-05）——1.5 是 2026 年轨迹级护栏的标杆；蚂蚁 SingGuard 双子（2026-07）则把"政策自适应 + 可插拔分类头"推成护栏工程化新路线。

AgentDoG 1.0（arXiv:2601.18491，2026-01-26，SJTU/复旦/PKU/UIUC/Shanghai AI Lab）不是单条消息分类器，而是诊断式轨迹级护栏：输入完整 Agent 执行轨迹（action–observation 序列）+ 工具描述，输出轨迹级 safe/unsafe 判定 + 三维细粒度诊断（风险来源 where × 失败模式 how × 现实后果 what），能识别"看似安全但不合理"的行为；4B/7B/8B 三档，模型与数据全开源，配套 ATBench。AgentDoG 1.5（arXiv:2605.29801，2026-05-28）轻量化到 0.8B/2B/4B/8B 四档（Qwen3.5 系），仅用约 1k 条影响函数净化样本训练：R-Judge 92.2% acc / 92.7 F1，ATBench 72.4%（较 1.0-4B +8.4），三维诊断均值 55.2%（GPT-5.4 为 25.8%）。可作在线 Pre-Reply 护栏（仅在最终交付前审计一次）：ClawSafety 上 ASR 从 56.25% 压到 18.75%，TTFT 亚秒级。局限：仅文本轨迹；只覆盖交付前检查点，无法阻止已发生的外部副作用。

SingGuard 与 SingGuard-NSFA：蚂蚁 inclusionAI 的护栏双子（2026-07-13 开源，Apache-2.0）

SingGuard（arXiv:2606.22873）是政策自适应多模态护栏：把安全政策作为运行时自然语言输入而非训练期固化分类法——部署方传入自定义规则，模型逐条比对并输出判定与命中的规则标题，规则热更新无需重训（与 gpt-oss-safeguard 同属 D 类政策推理路线）。基于 Qwen3-VL 发布 2B/4B/8B 三档，快-慢解耦强化学习支持"快速直判 ↔ 政策落地慢推理"双模式；默认政策 8 大风险类别，其中 E 类即智能体安全（系统提示/内部政策泄露）。官方报告其在 6 大评测家族、35 个数据集上平均 F1 全部第一（对标 Llama Guard 3、ShieldGemma、GPT-5.1、Gemini3-Pro），运行时政策切换下政策遵循准确率 0.6465→0.7415。SingGuard-NSFA（arXiv:2607.13081）是智能体行为护栏：基于 CIA 三元组交叉 3 份 OWASP 指南构建 7 一级域 / 28 二级风险 / 185 三级变体分类法，查询侧明确覆盖 Prompt Injection & Jailbreak、敏感信息窃取、危险工具滥用、资源耗尽；骨干 Qwen3.5-Base 0.8B/2B/4B/9B，四阶段合成数据管线扩展至 133 种语言。双模式输出：生成式 CoT 审计报告（合规场景）+ 判别式可插拔 MLP 分类头（冻结骨干、单次前向、45–57ms/样本）；官方口径四档 F1 均 >94%，分类头作插件装在 Llama Guard 3 上多语言 Query F1 67.66→85.23（+17.6）。NSFA 的判别头形态介于 A 类（判别式分类器）与 C 类（生成式判定）之间——无状态单轮进、多标签出、50ms 级，工程部署更接近 A 类。

口径提醒： SingGuard 与 NSFA 的全部基准均为蚂蚁自建，与 Qwen3Guard、Llama Guard 3 等的横向对比目前仅有官方口径、尚无第三方独立复测——引用其 F1 数字按本报告"厂商宣称"口径处理，不作为定论。两者训练数据规模未公开披露，故不入 §15 训练数据规模图（可确认的是 NSFA 使用 74 个开源 LLM 无种子生成的四阶段合成管线，基准集 inclusionAI/NSFA_Benchmarks 已公开）。对本报告主题的直接价值：185 变体中含专门的注入/越狱域、133 语言公开基准（NSFA-Query-Multilingual 63,431 条）、中文能力强，是 Qwen3Guard 在输入侧检测上的直接竞争者；"冻结骨干 + 可插拔分类头"也为存量护栏提供低成本升级路径。代码与权重全量开源（Apache-2.0，可商用），渠道覆盖 GitHub、Hugging Face 与 ModelScope。

2025Q4–2026.7 最新进展精选

新模型/框架： Llama Guard 4（Meta，12B 多模态，164K 上下文，单卡 24GB）；NVIDIA Nemotron-Content-Safety-Reasoning-4B（双模式：直接分类或带推理链按自定义政策执法，已进 NeMo 官方教程）；京东 JoySafety v2（Apache-2.0 生产级框架，DAG 策略引擎，内置多轮上下文注入检测——国产方案中少见直接覆盖多轮注入的选项）；CREST（XLM-RoBERTa 系，覆盖 100 种语言，主打低资源语言）；OpenAI safe-completions 范式（GPT-5：以"输出是否安全"替代"意图是否恶意"，防线从输入分类移向输出约束）。学术新方法： PIShield（hidden-state 线性检测）、PromptLocate（首个注入定位方法，"检测+切除"）、PromptArmor（现成 LLM 做检测+移除，AgentDojo FPR/FNR <1%，但 CUA 隐式注入检出仅 2–30%）、Meta SecAlign（完全开源的模型级内建防注入 LLM）、TRACES 类事中轨迹审计。

§10 · I/O 规格总表

每个方案吃什么输入、吐什么输出：六种 I/O 形态

接入管线时最先要问的问题——输入形态、role 概念、上下文上限、输出契约、阈值可调性、交付形态、延迟，一表对齐。

全部方案按 I/O 契约分六类：A encoder 分类器（单段文本进/标签+概率出，512 硬截断）、B 托管 verdict API（消息数组进/布尔出，普遍无连续分数）、C 生成式判定（对话进/需解析文本出，能吃 32K–164K 完整历史）、D 政策推理（政策+内容进/判定+理由出）、E token 级流式（token 流进/逐 token 标签出，唯一可生成中途止损）、F 轨迹审计（trace 进/诊断出）。F 类是唯一覆盖间接注入与目标劫持的形态——单消息分类器结构上看不到跨步意图偏离。NeMo Guardrails / LLM Guard / LlamaFirewall 整体属框架/编排器：I/O 形态由所挂检测器决定，框架只统一 is_valid/score/decision 的聚合口径。

接入注意点。 ① Azure 纯布尔无分数，灰度只能"先 log 不拦"；② Lakera breakdown 是 l1–l5 序数档不是概率，不能当 ROC 调阈；③ Qwen3Guard-Gen 输出必须正则解析，解析失败兜底是必写胶水代码；④ encoder 系 512 token 墙已被武器化（§12），长 prompt 必须切片且切片策略本身影响检出率——这是与生成式护栏最大的工程差异。

§11 · 多轮对话防护

没有任何单一轮次携带恶意载荷——检测单元必须升级为会话/轨迹

Crescendo / X-Teaming 类攻击单轮完全良性：单轮分类器对它们是结构性失效，不是调参问题。

攻击侧数据刺眼：Crescendo 对 GPT-4 二元成功率 98%、Gemini Pro 100%，平均 ASR 超出其他方法 29–71 个百分点且支持 backtracking；X-Teaming 四智能体自适应框架 HarmBench ASR 最高 98.1%，加大配置对 GPT-4o/Llama-3/DeepSeek-V3 达 100%。反直觉的是连"压缩"本身也成了攻击形态：M2S 证明多轮攻击可压缩成单条结构化提示（ASR 70.6–95.9%），利用的正是护栏的 contextual blindness——攻防同构。防御侧收敛为四类方法的组合拳：压缩检测（Defensive M2S：Qwen3Guard+hyphenize 压缩到 173 token 达 93.8% 召回，网关低成本首道筛）、会话级风险累积（网关侧 EMA/max 状态机，必须有衰减）、多轮感知护栏（全链路可见的末条判定器，长历史配混合窗口）、行为审计（AlignmentCheck/AgentDoG 轨迹级，组合把 AgentDojo ASR 压到 1.75%）。

落地组合。 首道筛：网关侧 Defensive M2S 式压缩 + 单轮分类器（173 token 成本拿 93.8% 召回）；会话状态：Redis 存 EMA 风险分 + 拒绝计数 + 历史最大分双通道（对外阈值 0.9、内部 0.5–0.6）；判定器：混合窗口（近期原文 + 早期压缩），Controversial 档走降级灰区；高权限场景加轨迹审计；用 PyRIT CrescendoOrchestrator / X-Teaming 开源实现做持续红队回归。

诚实边界。 会话级护栏在自适应多轮攻击下同样基本失守（SoK 实测三个 session-level 护栏对 X-Teaming ASR >90%）；无公开多轮 FPR 基准，良性长会话累积误拦（会话级 FPR ≈ 1−(1−p)ⁿ）缺乏量化参照。

§12 · 512 上下文墙

护栏只看 512 token，被保护的模型有 400K 窗口

主流开源注入分类器几乎都是 DeBERTa 底座，共享同一堵 512 token 墙——这是输入侧检测最结构性的短板，且缝隙已被武器化。

"What the Guardrail Inspects Is Not What the Model Infers"（USENIX Security 2026 方向）专门攻击这道缝隙：窗口外的内容无人检查。三个放大器：Lost in the middle（注入藏中段，"保首尾丢中段"的截断方向恰好反了）、Many-shot 幂律（长且重复的良性样式文本稀释逐块打分）、分块切断攻击句（两半各自无害）。中文另有换算陷阱：1 汉字≈1–2 token，512 token 约容 250–500 个汉字，一条中等长度中文消息就可能超窗。

方法：Semantic Scholar Graph API 逐篇拉 citations、按引用数排序、批量取摘要，辅以 4 组定向网页检索（检索时间 2026-07）。几条脉络值得点名：Qwen3Guard←GuardReasoner 是"推理式护栏"的嫡传——GuardReasoner 用 R1 式推理蒸馏让护栏先想再判，Qwen3Guard 把这条路线推到 119 种语言并补上流式版本；gpt-oss-safeguard←Instruction Hierarchy 说明 OpenAI 把指令层级思想从论文直接搬进了开放权重模型的训练管线；CaMeL/FIDES 一脉目前口碑最硬——在 Attacker Moves Second 的自适应攻击重测中，输入级检测器几乎团灭，只有架构隔离幸存，这直接催生了 2026 年向 Computer-Use、浏览器、Skill 场景的移植潮。

脉络趋势判断：三条趋势直接影响选型

  • 从"输入级分类器"转向轨迹级诊断。 2024–2025 的主角是 Prompt Guard、InjecGuard 这类输入分类器；2026 年的增量几乎全是 AgentDoG 式轨迹审计与 AttriGuard 式因果归因。含义：只买"输入网关"的产品已落后一个范式，评估工具时优先看它能否观测整条工具调用链。
  • 自适应攻击重测成为及格线。 Attacker Moves Second 之后，新防御论文被迫补做自适应攻击实验；PISmith 把这一过程自动化；"Learn Surface Heuristics"与"Firewalls All You Need"从两头证明静态基准高分没有信息量。含义：任何供应商报出的防御率，先问一句"自适应攻击下是多少"，答不上来就按无效处理。
  • 架构/因果隔离成为唯一幸存的主线。 CaMeL→FIDES→CUA 移植、Skill-Inject 对照实验一脉相承，训练侧 SecAlign 系也在向权限收缩（ProGent、MAC 框架）靠拢。含义：中长期押注应放在"结构性缩小攻击面"上，分类器只作纵深防御的第一道，不作唯一一道。

§14 · 论文精读选编

35 篇攻防论文逐篇精读：读完能改变防御设计决策的才入选

入选标准不是引用量，而是"读完之后能改变防御设计决策"——要么定义了一类威胁的失效机理，要么给出了可直接用于红队回归的攻击工具，要么实证推翻了某种防御假设。

按攻防主线分三组：攻击方法与威胁实证 11 篇（从 Jailbroken 的失效机理到 Skill-Inject 的供应链新面）、检测模型与护栏 12 篇（PromptShield 的低 FPR 铁律、Qwen3Guard、AgentDoG 轨迹诊断一脉）、防御架构与评测方法 12 篇（推理时变换 → 训练时对齐 → 架构级隔离 → 特权控制 → 评测与"打脸"文献）。核心结论先行：训练时方案（StruQ/SecAlign/Instruction Hierarchy）效果最强但不可纯推理时部署；架构级方案（CaMeL/FIDES/ProGent）是推理时唯一提供近确定性保证的路线；而 2025 年底以来的"打脸"文献表明，现有检测器与基准的可信度本身存疑。每篇条目给出研究问题、方法核心、关键数字，以及对 Agent 输入侧防护的一句话意义；数字均以原文或已核实综述为准。

"评测可信度"警示三角。 The Attacker Moves Second（自适应攻击重测 12 种防御几乎团灭）、Defenses Learn Surface Heuristics（检测器学到的是浅层特征而非注入语义）、Firewalls All You Need（玩具防火墙即接近"完美"，说明基准太弱）三篇共同构成本章的警示三角：任何防御数字，先问"自适应攻击下是多少"，答不上来就按无效处理。

§15 · 训练数据与微调

护栏模型的能力上限由数据决定，而不是由参数量决定

九个代表性护栏的训练数据明细、可复用的数据食谱规律、自建微调数据集操作指南与 LoRA 成本账目。

要点先行：绝大多数厂商不公开训练数据本身，公开配方的是少数。三个校准事实：其一，ProtectAI v2 是"训练集内指标虚高"的教科书案例——训练集 Accuracy 99.99%，未训练分布的 2 万条外测掉到 95.25%；其二，Prompt Guard 2 的触发词捷径是训练数据的结构性缺陷——私有基准 Recall@1%FPR 97.5%，但在 Lakera PINT（含大量 hard negatives）上只有 78.76%，NotInject 过防准确率仅 0.88%；其三，AgentDoG 1.5 证明窄任务下"对的 1,000 条"可击败大模型——4B 在 R-Judge 92.2% acc，细粒度诊断三维均值 55.2% 对 GPT-5.4 的 25.8%。

数据食谱的五条经验规律

  • 70:30 是良性:攻击的锚点配比。 ProtectAI v1 明确使用，qualifire Sentinel 独立复现同比例——线上流量里攻击是极少数，模型先验应匹配部署分布；但攻击侧必须按攻击族分层足量。
  • hard negatives 是第一优先级。 缺"像攻击的良性输入"，模型就学触发词捷径；InjecGuard 的 MOF 策略只混入 1,000 条含偏置 token 的良性样本，平均准确率即拉到 83.48%——纠偏成本极低，收益极高。
  • adversarial-benign 象限是防误报专用弹药。 WildGuard/WildJailbreak 四象限设计（adversarial-benign 达 78,706 条）让 WildGuard 把越狱攻击成功率从 79.8% 压到 2.4% 而不显著误杀。
  • 中文占比直接决定中文能力。 Qwen3Guard 训练集中文占 26.64%，是公开护栏里中文占比最高的，这直接解释了它的中文检出优势；多语言短板不是靠分类头能补的。
  • 数据质量 > 数量，有硬证据。 AgentDoG 1.5 约 1k 净化样本击败大模型；Aegis 2.0 用 34K 条 PEFT 微调 8B 持平用 3 倍数据训的 WildGuard；Tomoro 用 10k 垂直域数据 SFT Qwen3-0.6B，准确率 57% 对 gpt-oss-safeguard-120B 的 15%。

自建数据集操作指南（摘要）。 训练主粮：WildGuardMix（92K，CC-BY-4.0）、Aegis 2.0（34K，明确可商用）、TensorTrust（126K 真人玩家注入攻击）；避坑：WildJailbreak 研究用途门控、qualifire 系 CC-BY-NC 不可商用、jackhhao 标注争议大用前必须清洗。中文构造性价比最高的是翻译回译扩增（MBT-DA：正向翻译 3 版 → 回译校验 → 功能有效性校验）；攻击变体用 garak 批量产，上线后按 JoySafety 模式把脱敏真实攻击日志回流。标注必须相对"你的应用政策"、建议三级标签 + 3 人多数投票。防污染三条硬规则：评测集与训练集来源隔离；按攻击族分层切分（同族模板变体不得横跨 train/test）；跨源合并统一标签标准。数据量门槛：几百条可见效（MOF 1,000 条纠偏）、10k 级垂直域生产级、30k 级打平一线开源护栏。

训练方法与成本。 LoRA 远优于仅微调分类头：Sentinel-v2（598M）LoRA r=8 只训 2.3M 参数（−99.6%），单张 L40S、FP16、1 小时内、$1–2/run，垂直域 F1 0.97。推荐两层架构：小分类器预筛 + 生成式护栏复核。北极星指标 Recall@1%FPR；误报申诉样本是比攻击样本更稀缺的资产（正是 hard negative）。

能力边界声明（必须对管理层讲清楚）

  • 检测层的作用是抬高攻击成本、过滤 95% 脚本级攻击，不是保证安全。
