一页看懂 AHP 协议

Agent Host Protocol — 让 AI Agent 会话成为多客户端共享的基础设施

任意数量的客户端——VS Code 窗口、浏览器、CLI——同时挂载到同一个 AI agent 会话，看到完全一致的有序历史、终端状态与待批准变更。会话从"某个窗口的内部状态"，升级为 host 持有的权威共享资源。

规范 v0.6.0 · 草案阶段 · 预期破坏性变更 VS Code 1.129+ 灰度推送中 SDK × 5：Rust / TS / Kotlin / Go / Swift 与 ACP 分层互补 code agent host --tunnel
What · 是什么
开源的多客户端会话状态同步协议：不可变状态树 + 纯 Reducer + serverSeq 全序广播。
Stage · 什么阶段
规范 0.x 草案（0.6.0 已发布）；但参考实现已随 VS Code 1.121→1.130 产品化灰度。
vs ACP · 什么关系
分层互补：ACP 管 1:1 通信，AHP 管 N 客户端协调；host 上行 AHP、下行 ACP。
How · 怎么用
客户端用五语言 SDK / AHPX；远程走 SSH / Dev Tunnel；部署一行 code agent host。
01
Positioning · 先消歧

这个 AHP，不是那三个 AHP

"AHP" 缩写在 2026 年至少被四个项目占用。本页只讨论微软的 Agent Host Protocol（microsoft/agent-host-protocol）——"AI agent 会话的同步多客户端状态协议"。

  • ≠ Agent Harness Protocol（A3S-Lab）— agent 监督/策略执行
  • ≠ Agent Handoff Protocol — agent 向人类移交工作区
  • ≠ Agent Handshake Protocol — agent 发现网站的握手

它延续 LSP / DAP 的编辑器基础设施协议血统：LSP 时代会话属于一个窗口；agent 时代，AHP 把会话变成 host 持有的权威资源，客户端只是可随时来去的观察者与控制器。协议保持 agent 无关——不定义 agent 如何实现推理、工具与模型路由。

03
Architecture · 核心架构

状态复制协议，不是消息转发器：协调层 × 通信层

一切推送式交互发生在 channel（URI 标识的可订阅资源：ahp-root://、ahp-session:/<uuid>、ahp-chat:/<uuid>、终端、变更集）上；状态变更的唯一机制是 action，经纯 reducer 在服务器与客户端执行同一逻辑；host 用 serverSeq 全序广播——这条有序流就是所有窗口同步的依据。

04
vs ACP · 与 ACP 的关系

AHP 是协调层，ACP 是通信层

先消歧：此 ACP 是 Zed 发起的 Agent Client Protocol（编辑器↔agent 的"LSP"，Apache 2.0，JetBrains 全系已内置，60+ agent 接入）——不是 IBM 那个已归档并入 A2A 的 Agent Communication Protocol。

官方定位："AHP 是协调层，ACP 是通信层，二者天然组合"。心智模型：AHP 是 ACP 之上的互斥锁（mutex）——同一时刻每 chat 只有一个 turn；工具确认由 host 仲裁（第一个确认生效）；任何客户端可取消。AHP 不取代 ACP：客户端可以继续只说 ACP。

关注点AHPACP
多客户端协调核心目的（N 客户端同步）不处理（假设单客户端）
状态权威Host 持有权威状态树Agent 持有会话状态
变更定序serverSeq 全序广播请求-响应 + 流式通知
重连/回放内建（lastSeenServerSeq）协议层未规定
agent 抽象agent 无关agent 专属接口

  H-->>CA: chat/delta · chat/toolCallStart…
  H-->>CB: chat/delta · chat/toolCallStart…
  AG-->>H: 工具调用待确认（pending-confirmation）
  CB->>H: AHP · chat/toolCallConfirmed（B 批准，先到先得）
  H->>AG: ACP · 放行执行
  AG-->>H: 结果回传
  H-->>CA: chat/turnComplete
  H-->>CB: chat/turnComplete

协议全景分工：MCP 让能力可移植（Anthropic，工具/数据），ACP 让 agent 可移植（Zed，客户端↔agent），AHP 让活会话可移植（微软，N 客户端↔1 host），A2A 管 agent↔agent（Google / Linux Foundation）。四者不构成竞争。

05
Integration · 如何接入

两条路径：做客户端，或做 Host

绝大多数接入者走客户端路径——五语言官方 SDK 已在 crates.io / npm / Maven Central / Go proxy / SwiftPM 正式发版，另有 AHPX（CLI + Node）适合脚本自动化。Host 路径意味着参考 VS Code 实现自研服务器。

Sequence · 客户端接入握手与一轮对话
sequenceDiagram
  autonumber
  participant C as AHP 客户端
  participant H as Agent Host

  C->>H: initialize（protocolVersions[] · clientId · initialSubscriptions）
  H-->>C: protocolVersion · serverSeq · 快照（含 agent/模型列表）
  Note over C,H: 版本协商一次完成 · 不兼容返回 -32005 并关闭连接
  C->>H: createSession（ahp-session:/uuid · provider: copilot）
  C->>H: subscribe（ahp-session:/uuid）
  H-->>C: lifecycle: creating → session/ready（含默认 chat URI）
  C->>H: subscribe（ahp-chat:/cid）
  C->>H: dispatchAction · chat/turnStarted（写前乐观应用）
  H-->>C: chat/delta × N（流式，带 serverSeq）
  H-->>C: chat/toolCallStart → Delta → Ready（pending-confirmation）
  C->>H: chat/toolCallConfirmed（approved + reason）
  H-->>C: chat/toolCallComplete → chat/turnComplete
  Note over C,H: 断线？reconnect（clientId · lastSeenServerSeq）回放错过的 action

认证复用 OAuth 标准：RFC 9728 做受保护资源发现（AgentInfo.protectedResources），RFC 6750 Bearer 令牌经 authenticate 命令推送；过期时服务器发 auth/required。工程三建议：宽版本协商（传 SUPPORTED_PROTOCOL_VERSIONS）、先查 capability 再用新特性、重连直接用 MultiHostClient（自带 250ms→30s 指数退避 + 自动重订阅）。

Quickstart · 最小示例

TypeScript SDK 上手

import { AhpClient, AhpStateMirror }
  from '@microsoft/agent-host-protocol/client';
import { WebSocketTransport }
  from '@microsoft/agent-host-protocol/ws';

// 1. 连接 + 握手（含初始订阅）
const transport = await WebSocketTransport
  .connect('ws://localhost:12345');
const client = new AhpClient(transport);
const mirror = new AhpStateMirror();
client.connect();

const init = await client.initialize({
  clientId: 'my-client',
  protocolVersions: [...SUPPORTED_PROTOCOL_VERSIONS],
  initialSubscriptions: ['ahp-root://'],
});
for (const s of init.snapshots)
  mirror.applySnapshot(s);

// 2. 持续消费 action 流，镜像状态
const root = client.attachSubscription('ahp-root://');
for await (const ev of root)
  if (ev.type === 'action') mirror.apply(ev.params);

SDK 按职责拆四个子路径：默认入口（线路类型/reducer，无 I/O）、/client（AhpClient + 状态镜像）、/hosts（多 host 编排与重连监管）、/ws（WebSocket 传输）。浏览器与 Node 21+ 零依赖运行。

06
Remote · 如何支持远程 Agent

Host 贴着代码跑，客户端随处接入；合上笔记本，Agent 继续干活

与 VS Code Remote Development 同构：UI 留在客户端，工作区操作贴着源码运行。Agent host 是远端长驻进程——客户端全部断开后，运行中的会话仍继续执行；换台设备重连，看到的仍是同一份有序历史、终端状态、变更与待办。

方式前置条件机制适用场景
SSH远端可 SSH 直达（复用 ~/.ssh/config）Agents 窗口自动下载 CLI、启动 host、转发端口自有服务器 / 云主机
Dev Tunnel远端已运行 code tunnel（GitHub/微软账号认证）出站 WebSocket 隧道，无需入站端口无公网 IP、严格防火墙、浏览器/移动端
浏览器客户端host 已经 Dev Tunnel 暴露零安装轻客户端：看进度、批工具、管会话手机等任意设备

安全红线：AHP 端点访问控制是传输层责任、不在线路协议内。Dev Tunnel 必须要求账号认证（匿名隧道 = 任何人拿到 URL 就能触达你的机器并启动会话）；高影响命令与工具调用保持显式可审计的审批策略；协议不定义持久化、留存、静态加密与多租户——那是 host 实现者的责任。

07
Deployment · 怎么部署 Agent Host

一行命令起一个独立 Host

# 默认：监听 localhost，连接令牌保护
# （适合本机或配合 SSH 端口转发）
code agent host

# 通过 Dev Tunnel 对外暴露
# （供其他机器 / 浏览器客户端接入）
code agent host --tunnel

远端没有 CLI 的引导流程（Agents 窗口的 SSH 连接已全自动化）：

# SSH 到目标机 → 装 VS Code CLI → 起 host
curl -Lk 'https://code.visualstudio.com/sha/download?build=stable&os=cli-alpine-x64' \
  -o vscode_cli.tar.gz
tar -xf vscode_cli.tar.gz
./code agent host

Dev Tunnel 路线：目标机 code tunnel（首次 GitHub/微软账号认证，code tunnel service install 可注册为系统服务保活），客户端从隧道列表接入即可。

Three Forms · 三种运行形态

本地免部署，远程一条命令，自建可参考实现

形态启动方式说明
Agents app + 本地 hostchat.agentHost.enabled: true 后重启agent 选择器出现 Copilot CLI [Local] 即生效
VS Code + 本地 host同上，选 Agent Host - Copilothost 为本地 utility 进程，MessagePort IPC
+ 远程 hostSSH 或 Dev Tunnel 连接远端独立进程，AHP over WebSocket

本地形态零手工部署：VS Code 自动拉起 host 进程，Copilot / Claude / Codex 第一方适配器运行在 host 内做翻译。协议开放，官方欢迎"任何人构建 VS Code 能连接的 AHP host"——但需自行承担：channel 路由、状态树与 reducer 一致性、serverSeq 广播、快照+回放、版本协商（-32005）、RFC 9728/6750 认证、agent event mapper 事件翻译，以及持久化/多租户/审计。服务器端目前仅 VS Code 一个实现，自建属早期互操作工作。

Verdict · 结论与建议

纳入"观察 + 试点"象限：用它做原型低风险，当生产硬依赖为时尚早

客户端开发者
现在就可基于五语言 SDK / AHPX 构建连接 VS Code agent host 的自定义 UI 与自动化；用宽版本协商 + capability 检查防御 0.x 的破坏性变更节奏。
平台 / 企业团队
把"远程长驻 agent + 浏览器轻客户端"纳入远程开发规划；先定好隧道策略、审批默认值、工具归属（扩展工具 vs MCP server）再灰度。
Agent / 工具厂商
短期更现实的路径仍是先接 ACP（Registry 一次注册、多编辑器分发）；AHP host 侧适配留给微软与社区成熟——host 生态目前还是单一参考实现。

主要风险：规范未稳定（官方明示破坏性变更预期）· 服务器端单一实现的事实锁定 · 远程模型把传输层认证、审批、持久化与审计责任转移给部署者。
